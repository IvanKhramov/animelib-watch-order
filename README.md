# animelib-watch-order

Userscript для animelib.org и animego.me. На странице аниме, прямо перед блоком «Связанное», появляется блок «Порядок просмотра» со всей аниме-веткой франшизы. Основная линия пронумерована, дополнительное (OVA, спешлы, рекапы) стоит между частями по дате выхода, альтернативы и спин-оффы свёрнуты отдельно. Ссылки ведут только на тот же сайт.

Скрипт не трогает плеер, авторизацию и региональные ограничения.

## Установка

1. Поставить [Tampermonkey](https://www.tampermonkey.net/) или [Violentmonkey](https://violentmonkey.github.io/).
2. Открыть ссылку **[animelib-watch-order.user.js](https://raw.githubusercontent.com/IvanKhramov/animelib-watch-order/main/dist/animelib-watch-order.user.js)**, менеджер предложит установить скрипт.
3. При первом запуске разрешить доступ к `graphql.anilist.co` («Всегда разрешать домен»).
4. Открыть страницу любого аниме. Блок появится сам, перед «Связанное».

Обновления менеджер подтягивает сам по `@updateURL`. В Chrome с Manifest V3 для Tampermonkey нужно включить «Разрешить пользовательские скрипты» в `chrome://extensions` → Tampermonkey → «Сведения».

## Что умеет блок

- «Основное / Всё»: только основная линия или вместе с OVA, спешлами и рекапами.
- Кружок слева: отметить просмотренным. В свёрнутом виде видно, сколько просмотрено и что смотреть дальше.
- «Править»: поменять части местами стрелками, скрыть лишнее, вернуть скрытое. Порядок хранится для всей франшизы и одинаков на всех её страницах.
- Стрелка у заголовка сворачивает блок. «⋯» → «Скрыть блок на этом сайте»; вернуть: меню Tampermonkey → «Показать/скрыть „Порядок просмотра“».
- «⋯» → экспорт и импорт отметок в JSON для переноса в другой браузер.

Всё это хранится локально в хранилище менеджера скриптов, никуда не отправляется.

Лицензированные тайтлы AnimeLib без логина отдают 404. Если на сайте залогиниться, скрипт берёт токен самого AnimeLib из `localStorage.auth` и отправляет его только в API AnimeLib.

## Откуда данные

- AnimeLib API (`api.cdnlibs.org` или `hapi.hentaicdn.org`, хост берётся из запросов страницы, `Site-Id: 5`): `/anime/{slug}/relations` (анонимно), `/anime/{slug}` (карточка: `anilist_id`, дата), `/anime?q=` (поиск, у результатов часто есть `anilist_id`).
- animego: SSR-страница, JSON-LD (английское название, дата) и блок «Связанное».
- AniList GraphQL: граф связей (`PREQUEL`/`SEQUEL`/`SIDE_STORY`/...), форматы и даты. Через `GM_xmlhttpRequest` с `anonymous: true`, только публичные id и названия.

Порядок строится по связям PREQUEL/SEQUEL и датам выхода AniList. Это рекомендованный порядок, а не каноническая хронология. Если AniList недоступен, блок показывает порядок только по связям сайта с пометкой о неточности.

## Сопоставление AniList и сайта

Принимается только взаимно-однозначная пара: тот же `anilist_id`, либо точное совпадение названия (после нормализации) при совместимых формате и годе. Совпадение по названию помечается «≈ по названию», его можно убрать кнопкой «не то». Ненайденное показывается как «Не найдено на сайте» со ссылкой на поиск по каталогу.

Отметка «просмотрено» ставится только вручную.

## Разработка

```sh
npm install
npm run check    # tsc + vitest + сборка
npm run build    # dist/animelib-watch-order.user.js и dist/preview-inject.js
```

`dist/preview-inject.js` нужен для ручной проверки без менеджера userscript: та же логика плюс GM-обвязка поверх localStorage. Его можно вставить в консоль браузера на странице тайтла.

Структура `src/`: `anilistAdapter`, `matching`, `orderPolicy`, `watchOrder` (сборка результата), `storage`, `ui`, `spaLifecycle`, `sites/` (адаптеры animelib и animego).

## Ручной smoke test

1. AnimeLib, `/ru/anime/14986--haikyuu-to-the-top-anime?ui=1`: один блок перед «Связанное», текущий тайтл под номером 5, OVA и фильмы между сезонами.
2. Перейти по карточке в «Связанное» без перезагрузки: блок пересобрался, «Вы здесь» переехал.
3. Переключить вкладку тайтла: блок пропадает, при возврате появляется снова, дублей нет.
4. animego, `/anime/moya-reinkarnaciya-v-otome-igre-v-kachestve-glavnoy-zlodeyki-2-1808`: блок перед «Связанное».
5. Узкий экран (около 400px) и тёмная тема: строки переносятся, текст читается.
